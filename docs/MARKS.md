# 标记与持久化

## 标记模型

拾影为每张逻辑照片维护两个独立属性：多选颜色标记与待删除状态。颜色包含橙、黄、绿、蓝、紫、灰；浏览、大图、对比和编辑页面均可通过右键菜单设置或清除。

颜色点显示在文件名旁。主页支持按一种颜色筛选，并与相册、搜索和待删除分类组合；待删除确认和实际操作目标均遵循当前颜色筛选范围。待删除只是筛选意图，不会立即移动文件。

## 目录结构与记录身份

每个照片文件在其所在目录的 `.photoharbor-marks/` 中保存独立 JSON，记录文件名为原文件名的 SHA-256 摘要。

```text
相册目录/
├── PHOTO.JPG
├── .photoharbor-marks/
│   └── <文件名摘要>.json
└── .photoharbor-originals/
    └── <编辑备份及校验记录>
```

JPG 与 RAW 位于不同目录时，两侧分别保存记录。标记记录包含版本、文件名、文件字节数、文件身份、修改时间、颜色集合、待删除状态和更新时间，不包含绝对路径或 EXIF。原始照片内容不因设置标记而改变。

## 读取与一致性规则

- 读取记录时校验版本、大小和文件名，并拒绝损坏或符号链接记录。两种标记统一核对文件身份和修改时间。
- 配对成员的记录均有效时，采用最新记录。
- 任一成员的文件版本发生变化时，原有颜色和待删除标记均不继承。
- 清空标记后保留空记录，防止另一侧较旧的记录重新启用标记。

设置或清除两种标记都无需读取照片内容。缺少文件身份的第一版记录继续通过原有内容摘要验证，下一次写入时升级。

## 写入与故障处理

写入前核对全部配对文件的身份、大小和修改时间，完成记录准备后逐项原子更新。写入成功后才更新界面状态；失败显示错误，普通失败尽量回滚已写入副本。照片所在目录必须可写。

不同磁盘上的更新没有跨卷事务保证。断电或回滚失败可能留下不一致副本，重新加载时按有效性和更新时间合并。损坏记录不自动覆盖修复。

## 移动、编辑与迁移

| 场景 | 行为 |
| --- | --- |
| 关闭后重新打开相册 | 从照片目录恢复有效标记。 |
| 从独立配置打开相册 | 无需旧 `state.json`，可读取随照片保存的有效标记。 |
| 移动整个相册目录 | 保留 `.photoharbor-marks/` 且文件身份和修改时间不变时可恢复标记。跨卷复制通常会改变身份。编辑备份需保留 `.photoharbor-originals/`。 |
| 仅移动单个照片或重命名 | 不自动跨目录查找，也不沿用原名记录。 |
| 应用内保存或还原 JPG | 颜色记录刷新至新版本，待删除状态清除。 |
| 外部替换照片 | 原有颜色和待删除标记均不继承。 |

旧版本的待删除状态位于本机 `PhotoHarbor/state.json`。扫描时迁移有效旧标记；迁移失败会提示，并保留尚未迁移的本机记录。`state.rejected` 继续作为兼容缓存，目录记录优先。

## 与删除恢复记录的区别

| 数据 | 保存位置 | 生命周期 |
| --- | --- | --- |
| 颜色 / 待删除标记 | 照片同级隐藏目录 | 可随相册移动，关闭相册不清除。 |
| 废纸篓恢复批次 | 本机 `state.json` | 绑定相册与废纸篓路径，关闭或失联相册后清理；对应文件消失后失效。 |

照片成功移入废纸篓后，记录清除待删除状态并保留颜色，恢复文件后不会继续被选为待删除。恢复批次不能作为可随目录迁移的照片标记。

隐藏记录不参与照片扫描，但包含个人筛选偏好、文件名和摘要，不应提交仓库。测试与隐私要求分别见[开发指南](DEVELOPMENT.md)和[隐私文档](PRIVACY.md)。

## 批量标记

主页多选可为当前选中的照片批量设置颜色和待删除标记。单张配对照片可并行核验两份文件，批量操作最多同时处理三张照片。完成后合并成功的标记更新，普通浏览复用现有列表，标记筛选按稳定的照片身份增删照片卡片。单张失败会报告，其他已成功保存的标记保留。


相册标题右侧的废纸篓菜单支持移入废纸篓或直接删除。确认清单只包含当前相册内的待删除照片，搜索和颜色筛选不影响范围。

在「设置 → 存储」中可独立设置单张照片标记等待上限（默认 60 秒，可选 30 至 180 秒）和删除无进展提醒（默认 90 秒，可选 30 至 600 秒）。升级后原来的等待设置沿用为标记上限。批量标记为每张照片单独计时。批量删除持续核对或处理文件时可以超过提醒设定的时间，核对相册和直接删除文件的并发任务分别记录最后进展。任一任务停滞后暂停安排后续操作，关闭进度窗口，等待已提交的操作返回。系统废纸篓只返回整批结果，提醒出现后仍会等待系统确认。删除结果会先显示，相册刷新另行进行，刷新期间继续锁定文件修改。
