# 隐私与公开仓库边界

## App 的数据

照片留在用户选择的目录，不上传到项目服务器。没有账号、第三方分析或遥测服务。本机 Vision 评测不上传照片；GPS 地点反查通过系统 CoreLocation 服务进行，可能向系统服务发送坐标，需要网络。无法反查时使用「未知」。

默认状态在 `~/Library/Application Support/PhotoHarbor/state.json`，包含用户目录路径、相册、标记和删除恢复记录。导入的 `import-UUID.json` 含来源与目标路径。不要提交、公开或附到 issue 中。排错请使用 `PHOTOHARBOR_STATE_PATH` 指向隔离合成数据。

## 允许提交

源码、合成测试生成器、无用户数据的文档、正式图标源图、构建脚本和 CI。图标已移除 PNG 的文本、EXIF 与时间元数据。真实相片及其缩略图不属于仓库资源。

## 禁止提交

- 任何访问令牌、密码、私钥、证书私钥、签名证书、SSH / 云服务凭据、`.env`。
- 私人邮箱、本机用户名绝对路径、挂载盘 / NAS 信息、个人相册配置、导入清单及日志。
- 含个人照片的截图、测试报告、真实 RAW / JPG、导出的模型评测。
- 构建产物、缓存、应用包、本地设计与历史归档。

`.gitignore` 排除常见敏感路径，`scripts/check-repository.rb` 检查 Git 已跟踪及已暂存新增文件，拒绝危险文件名、常见令牌 / 私钥格式、个人绝对路径、大文件和非允许的二进制资源。扫描只报告文件与规则，不回显可疑内容。规则是辅助防线，不能证明不存在所有隐私问题；公开前仍需人工检查整个暂存区。

```sh
ruby scripts/check-repository.rb
# 查看文件清单，再在本机审阅补丁；不要将敏感 diff 粘贴到公开渠道
git diff --cached --stat
git diff --cached
```

GitHub 登录通过个人终端 / 系统凭据存储完成。不要把令牌写进 remote URL、脚本、Git 配置或 PR。提交身份优先使用 GitHub noreply 邮箱。

## 发现泄露

不要在公开 issue 中贴出凭据。先撤销 / 轮换受影响凭据，再清理文件及 Git 历史；单纯删除当前文件不足以从历史消除泄露。联系仓库所有者处理。运行脚本检查通过不替代这一流程。
