# 隐私与数据处理

## 处理原则

照片保留在用户选择的文件目录中。拾影没有用户账号、项目照片上传服务、第三方分析或遥测。本机编辑、滤镜应用和 Vision 评测不上传照片。

GPS 地点反查在 macOS 26 及以上使用系统 MapKit 服务，旧系统使用 Core Location，可能向系统服务发送坐标并需要网络。反查失败时地点回退为「未知」。这是照片导入中的可用地点来源，不属于图像编辑或评测流程。

## 本机数据清单

| 数据 | 默认位置 | 内容与注意事项 |
| --- | --- | --- |
| 应用配置 | `~/Library/Application Support/PhotoHarbor/state.json` | 目录路径、相册配置、兼容标记缓存及废纸篓恢复记录。 |
| 导入完成列表 | 任务内存 | 导入结束后释放。旧版生成的 `import-UUID.json` 或 `import-UUID.jsonl` 仅用于人工排查，可删除。 |
| 滤镜与 LUT 库 | 状态目录中的 `Filters/`、`LUTs/` | 资产副本、名称、摘要及兼容性信息；不保存导入来源路径。 |
| 原始 JPG 备份 | 照片同级 `.photoharbor-originals/` | 最初照片和校验记录，可能保留完整拍摄元数据。 |
| 颜色 / 待删除标记 | 照片同级 `.photoharbor-marks/` | 文件名、文件身份、大小、修改时间、标记及更新时间，不含绝对路径和 EXIF。旧版本记录可能含内容摘要。 |
| 评测、选择及未保存调整 | 会话内存 | 退出相应会话后不持久化。 |

隐藏目录也是个人照片数据的一部分。普通删除不会清除原始 JPG 备份；共享、移动、备份或清理相册时，应同时考虑这些目录的内容。废纸篓恢复批次包含本机路径，不能作为可携带的标记记录使用。

XMP 解析禁止 DTD 和外部实体，不访问预设中的外部文件或网络引用。第三方滤镜和 LUT 的使用权由其各自许可证决定。

## 公开仓库边界

允许提交源码、合成测试与生成器、无用户数据的文档、正式图标源图、构建脚本和 CI 配置。真实照片、个人预设及应用运行数据不属于仓库资源。

禁止提交：

- 访问令牌、密码、私钥、签名证书及其私钥、SSH / 云服务凭据和 `.env` 文件。
- 私人邮箱、个人用户名绝对路径、挂载盘 / NAS 信息、相册配置、导入清单和原始日志。
- 真实 JPG / RAW、个人照片缩略图、含个人照片的截图及评测导出。
- 应用包、编译缓存、构建输出、本地设计草稿和历史归档。

`.gitignore` 排除常见凭据、照片、预设、隐藏记录和构建目录。`scripts/check-repository.rb` 检查已跟踪及暂存新增文件，识别危险文件名、常见凭据模式、个人路径、大文件和非允许二进制资源；输出仅包含文件与规则，不回显可疑内容。

自动扫描不能证明不存在所有隐私问题。公开提交前仍须人工审阅完整暂存区：

```sh
ruby scripts/check-repository.rb
git diff --cached --stat
git diff --cached
```

GitHub 登录应通过个人终端或系统凭据存储完成，不将令牌写入 remote URL、脚本或提交说明。提交身份优先使用 GitHub noreply 邮箱。问题复现使用 `PHOTOHARBOR_STATE_PATH` 指向隔离合成数据，避免公开个人配置。

## 泄露处理

发现凭据泄露时，首先撤销或轮换相关凭据，再清理文件与 Git 历史；删除当前文件不能消除历史副本。不要在公开 Issue 或 Pull Request 中粘贴凭据、完整个人路径或未经脱敏的日志，应联系仓库所有者处理。
