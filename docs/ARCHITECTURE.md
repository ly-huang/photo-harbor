# 架构设计

## 设计范围

拾影采用基于文件目录的照片管理模型。应用不建立独立的照片数据库，也不将照片迁入专有图库；JPG / RAW 配对关系由扫描结果推导，用户配置、标记及文件操作记录通过 JSON 持久化。

系统分为界面、应用状态、领域服务和文件存储四个层次。界面负责呈现和输入，`LibraryStore` 协调相册与窗口，领域服务负责扫描、导入、评测和编辑，存储模块负责文件身份验证与持久化。

## 状态与存储归属

| 数据 | 生命周期与存储位置 |
| --- | --- |
| 相册配置、目录路径、删除恢复批次 | 默认位于用户 Application Support 中的 `PhotoHarbor/state.json`。 |
| 导入完成列表 | 仅在导入任务的内存中保留，用于进度与相册登记。 |
| 颜色和待删除标记 | 照片同级 `.photoharbor-marks/`；`state.rejected` 仅作为兼容缓存。 |
| 最初 JPG 及编辑校验记录 | JPG 同级 `.photoharbor-originals/`。 |
| 用户 LUT / XMP 库 | 状态目录中的 `LUTs/` 和 `Filters/`。 |
| 评测、对比选择、未保存编辑及撤销栈 | 进程或编辑会话内存，退出后不持久化。 |

`PHOTOHARBOR_STATE_PATH` 可覆盖默认配置路径，用于隔离开发与测试。标记和原始备份的详细协议分别见 [MARKS](MARKS.md) 与 [EDITOR](EDITOR.md)。

大图预加载与前台查看合并同一路径进行中的后台属性查询，并按文件版本合并解码。详情面板按照片版本缓存最近读取的拍摄参数，读取失败时可重试。局部刷新只检查相关相册的废纸篓文件是否存在。批量导出复用受保护文件的路径和身份索引，可能存在硬链接时即时复核文件身份。

## 相册打开与分类导入

### 打开已有相册

扫描时优先使用目录枚举返回的文件编号、创建时间与卷信息。每个根目录先核对枚举结果是否与原有文件身份一致，资料不全、卷不同或校验不一致时逐文件查询。

启动只触发一次自动扫描。扫描与标记核验在后台执行，单相册并行读取两种格式，多相册最多并行三册并优先扫描当前相册，逐册发布可浏览结果，完整扫描结束后更新删除状态和撤销记录。扫描期间保留写操作的互斥保护。缩略图复用扫描时读取的文件身份、大小和修改时间作为缓存版本，避免在视图刷新时查询 NAS。侧栏显示已保存的路径，照片身份在配对时生成，界面可直接复用。扫描在内存中按标记目录建立文件名索引，存在记录时按标记类型核验文件属性或内容摘要，目录无法列出时回退到逐文件读取。打开新相册只刷新目标相册，其余使用会话内的快照。批量打开在后台枚举 JPG / RAW 根目录的一级非隐藏子目录，以目录名分组，组间独立配对。若同时存在直属照片与子目录，提示用户选择整库打开或单独选目录。批量登记一次保存，目录重叠时保持原相册列表。

相册可配置 JPG 和 RAW 两个根目录，至少提供一个。打开操作只扫描和配对，不复制、分类或移动文件。应用支持多个独立相册，拒绝重叠根目录，避免同一文件被重复管理。关闭相册会清理对应会话与删除撤销记录，保留照片和目录内标记。批量关闭一次保存相册列表，清理在线和离线会话、选中照片及筛选状态。保存失败时回滚相册配置。

编辑保存或撤销删除后仅刷新受影响的相册。应用激活时在后台检查相册可用性和废纸篓记录，十秒内合并重复的激活请求，删除历史变化时才写盘。执行恢复时在后台核验目标相册，逐项处理且拒绝覆盖现有路径。需要创建目标目录或遇到错误时重新核验。批次结束后合并保存历史，若中途退出，下次检查会清理已移出废纸篓的记录。

### 分类导入

导入分为计划和执行两个阶段。取消预览会取消后台计划任务，界面立即恢复并丢弃该任务的结果。计划阶段每个来源扫描一次，界面预览最多同时扫描三个来源，汇总时按来源列表顺序处理。省去仅供相册身份核验的文件属性读取。界面预览最多并行读取四张照片的元数据，已从 JPG 取得所需信息时跳过 RAW 元数据读取。最终地点确定后读取并复用目标目录列表，名称完全一致时直接采用目录列表，大小写不同的候选再逐文件确认，发布时仍重新核验。可关闭在线 GPS 反查，继续使用嵌入地点或未知分类。执行时使用 4 MiB 数据块边复制边计算来源 SHA-256，保留文件元数据，再读回临时目标验证摘要。执行时最多并行准备两份临时副本，按计划顺序发布。完成列表仅用于本次导入的进度和相册登记。失败或取消会清理未发布副本。发布前复核来源身份、大小、修改时间及目标路径。导入后重扫受影响的相册并复用其他相册的快照，注册失败时回退到全量刷新。导入后选中本批次按名称排序的第一个成功注册的相册。重载完成后，界面将侧栏滚动到该相册，状态栏列出本批次成功打开的相册。

```text
JPG 根目录 / YYYYMMDD_地点 / 原文件名
RAW 根目录 / YYYYMMDD_地点 / 原文件名
```

地点优先级为手动输入、IPTC 信息、GPS 反查，最终回退为「未知」。macOS 26 及以上使用 MapKit 返回的城市名，旧版 Core Location 可返回市区组合。缺失拍摄时间时提示使用文件修改时间；配对文件保持一致的分类日期。两个目标位置相同时，在该位置下分别创建 `JPG/` 与 `RAW/` 子目录。

多个来源共用目标根目录，独立配对并汇总重叠路径。来源检查汇总所有扫描失败和配对歧义，列出具体路径，在生成计划和复制前停止。同批相册内主文件名冲突时，为后续照片分配共同后缀，避免跨来源误配。预览标出已有同名文件。跳过和保留两者按配对处理，改名时两种格式共用数字后缀。替换只作用于预览标出的同名目标，预览后新出现的冲突仍会阻止写入。文件独立校验和发布，批次中止时保留已完成项。

## 文件操作约束

以下约束是修改扫描、导入、删除或恢复逻辑时必须保持的行为：

1. **配对唯一性**：优先使用相对相册路径与文件主名配对，忽略大小写；备用匹配仅在两侧主名均唯一时使用。存在歧义的照片不可执行成对删除。
2. **身份核验**：扫描跳过符号链接；写入或移动前重新检查根目录、文件身份及预期属性。离线目录不解释为空相册。
3. **导入不覆盖**：来源文件保留，默认不覆盖目标。只有在导入预览中明确选择替换后，才会核验已标出的普通文件版本并执行替换。流式 SHA-256 校验通过后发布。中断保留已发布文件，重试不自动覆盖或续传。
4. **标记不误继承**：颜色和待删除状态均绑定文件身份、大小和修改时间。缺少文件身份的第一版记录仍通过原有内容摘要验证。
5. **删除可恢复**：默认删除经确认后进入系统废纸篓，按相册和操作批次记录。显式确认的直接删除绕过系统废纸篓，逐文件重新核验身份，不创建撤销记录。恢复不覆盖已有文件，单项失败不阻止其他项目继续。
6. **恢复记录有界**：相册关闭、失联或废纸篓文件不存在时，相关恢复记录会清理或失效。

文件移动与记录更新不具跨卷或断电事务保证。JPG 编辑是明确的覆盖例外，必须遵守首次备份、摘要验证与发布协议。

删除前从待删除列表冻结本次文件集合，最多并行核对三个受影响相册的配对和属性，全部核验通过后才执行。相对路径一致的配对只遍历相关目录分支。跨目录匹配或单文件照片仍查找相册中所有同名候选，仅对候选读取文件身份。移入废纸篓使用一次 `NSWorkspace.recycle` 调用，根据系统返回的原路径和目标路径建立撤销批次。直接删除使用最多四张照片的滚动并发队列，逐文件复核属性后删除，单张失败后继续处理其他照片。进度窗口显示当前阶段和直接删除时已处理的照片数。全部任务结束后只刷新有文件变动的相册。

筛选导出是独立复制流程，不修改导入的不覆盖规则。导出面板快照当前可见照片，来源属性变化时拒绝复制；同名文件默认保留两者，替换必须逐项明确选择并复核目标身份、大小、修改时间和状态变更时间。禁止替换当前管理的任一来源路径或其硬链接；符号链接目标不允许替换。导出边复制边计算来源 SHA-256，核验临时副本内容和来源文件属性后发布，保留两者的发布不覆盖新出现的目标。替换使用系统原子替换接口，检查与发布之间不提供对外部并发写入的事务隔离保证。每个文件独立处理，部分失败或停止不回滚已完成项；数字后缀也按文件分配，可能改变 JPG / RAW 的同名关系。

## 窗口、视野与评测

大图与对比分别复用一个独立 `NSWindow`。从浏览页打开其他照片会更新并激活已有窗口，包括全屏窗口。每个画布独立维护缩放比例与偏移；当前画布的「适应窗口」不改变其他照片视野，「全部适应」通过共享 token 通知各画布。

工具栏和评测面板分别维护自动隐藏与固定状态。固定评测面板占用独立侧栏，悬浮评测面板覆盖照片边缘并避开标题栏。对比选择最多四张；清空选择不修改文件或标记。

主页缩略图采用 512 MiB 的 NSCache 成本预算，由系统执行淘汰，属于软限制。缩略图请求绑定视图任务，取消后跳过尚未开始的解码；已开始的 ImageIO 读取允许完成，队列最多并发三项。网格请求优先于其他缩略图请求。大图 `ViewerImageCache` 将当前照片和后台预加载分到独立的串行解码队列，已缓存照片无需等待后台解码，按实际 `bytesPerRow × height` 计费，缓存预算为 1024 MiB。以当前可见列表中的当前照片为中心，依次预加载下一张、上一张及更远邻居，不设照片张数限制。空间不足优先淘汰距离更远的图像，尺寸预估超出预算时停止预加载。切换取消旧任务。新中心附近有缓存时保留同列表条目，按距离淘汰并补齐近邻。跳到无缓存的远处时清理旧窗口并重新预加载。导航小图在首次显示导航时生成。关闭大图清空缓存。缓存键包含文件身份、大小及修改时间，避免编辑后复用旧图。当前画布、对比画布、编辑器及解码临时分配的内存独立于缓存预算，预算不代表进程总内存上限。

macOS 15 及以上使用 Vision Swift 请求获取审美评分和第二版图像特征，macOS 14 的相似度使用兼容接口。审美参考来自 Vision，原始值线性映射至 0–100；特征距离越小表示越相似，但不是相似概率。细节能量、近黑 / 近白比例和直方图基于降采样预览计算，不等同于对焦准确率。大图预览长边最高 8000 像素，不保证原片逐像素显示。

普通浏览时，手形指针仅用于放大后可平移的图像区域。顶部状态栏、图片外留白和浮层控件使用箭头；裁剪、画笔和编辑前后分割保留各自的工具指针。

大图使用 Dispatch 内存压力通知执行预算降级。每次 warning 将预算减半，低于 64 MiB 后降至零，按最远优先释放缓存；critical 立即将预算清零并暂停预加载。无缓存时仍可解码当前照片，画布持有的图像独立于缓存。normal 后以最多 64 MiB 恢复，后续切换在压力正常时逐次翻倍至 1024 MiB。该策略避免持续占用最大预算，但不能保证系统在突发分配失败前一定通知，也不能捕获所有底层内存耗尽终止。

## 编辑并发与一致性

编辑状态由主线程模型持有，Core Image 处理由后台 actor 隔离。预览使用缩小图，单个渲染循环合并连续输入，发布几何一致的编辑前后预览，并最终收敛至最新参数。保存重新读取全尺寸 JPG。

`ImageGeometryPlan` 统一保存、预览、参考图与画笔反算的变换。编辑前参考图、滤镜缩略图和 LUT 解码结果按受限策略缓存。系统补充参数控件使用稳定标识访问配方；撤销或还原移除参数后，旧绑定读取中性值，避免失效下标访问。

保存或还原后重新扫描照片、恢复路径选择并失效相关缩略图及评测缓存。颜色标记刷新到新文件版本，待删除状态清除；旧对比选择不自动继承。
